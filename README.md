# Transcribator

Расшифровка аудио и видео в документы Word с разделением по говорящим.
Работает локально на видеокарте, ничего никуда не отправляет.

* Распознавание речи — **Whisper large-v3** через `faster-whisper`
* Разделение говорящих — **pyannote.audio** (`speaker-diarization-community-1`)
* Результат — файл `.docx` с таймкодами и подписями «Спикер 1», «Спикер 2»
* Есть графическое окно и запуск из командной строки

На ноутбучной RTX 4050 (6 ГБ) с моделью large-v3 распознавание идёт
**в 12 раз быстрее реального времени**, с разделением говорящих — примерно
в 8 раз: час записи превращается в документ за 7–10 минут. В пакете модели
загружаются один раз, поэтому каждая следующая запись идёт ещё быстрее.
Все числа ниже — замеры на этой же машине.

## Установка

**Готовый установщик** для Windows лежит на странице
[Releases](https://github.com/6snowyfox6/Transcribator/releases) — около 2 МБ.
Он сам найдёт или скачает Python, определит видеокарту и поставит нужный
вариант PyTorch. Подробности — в разделе «Передача коллегам» ниже.

**Из исходников**, если хотите собрать сами:

```
git clone https://github.com/6snowyfox6/Transcribator.git
cd Transcribator
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu128
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Нужен Python 3.10–3.13 (не 3.14: под него ещё нет сборок `pyannote.audio`).
Без видеокарты NVIDIA поставьте PyTorch с индексом `.../whl/cpu` — работать
будет, но примерно в 20 раз медленнее.

## Токен Hugging Face

Модель разделения говорящих скачивается только авторизованным пользователям.
Регистрация и токен бесплатные, настройка разовая. При первом запуске окно
проведёт по этим шагам само; вручную это выглядит так:

1. Зарегистрируйтесь: <https://huggingface.co/join>
2. Откройте <https://hf.co/pyannote/speaker-diarization-community-1>
   и нажмите **Agree and access repository**. Одного токена недостаточно:
   согласие привязано к аккаунту.
3. Создайте токен: <https://hf.co/settings/tokens> → **Create new token** →
   тип **Read** → строка вида `hf_xxxxxxxx`.
4. Сохраните её в файл `hf_token.txt` в этой папке (одна строка).

Файл `hf_token.txt` — это пароль от аккаунта Hugging Face: не выкладывайте
его в общий доступ. В `.gitignore` он уже внесён.

Без токена всё остальное работает — запускайте с ключом `--no-diarization`,
тогда получится сплошной текст без подписей говорящих.

## Как пользоваться

**Способ 1 — окно программы (проще всего).** Запустите `Транскрибатор.bat`
двойным кликом. Откроется окно: перетащите в него записи или добавьте кнопками,
при необходимости поменяйте настройки и нажмите «Начать расшифровку».

В окне видно, какой файл обрабатывается и сколько осталось, а кнопка
«Остановить» прекращает работу в любой момент. Настройки запоминаются
до следующего запуска (файл `gui_settings.json`).

Вкладка **«История»** хранит все расшифровки: когда, что, сколько заняло,
сколько нашлось говорящих. Двойной клик открывает готовый документ, есть
кнопки «Показать в папке» и «Расшифровать заново». История пишется и при
запуске из командной строки — это один общий журнал (`history.jsonl`).

Поле **«Имена и термины»** — подсказка модели. Если вписать туда участников и
специальные слова («Совещание. Участники: Иванов, Петрова. Термины: EBITDA»),
они будут написаны правильно, а не на слух.

**Способ 2 — перетаскиванием.** Перетащите один или несколько файлов (или целую
папку) на `Расшифровать.bat`. Документы Word появятся рядом с исходниками.

**Способ 3 — папка input.** Положите файлы в `input\` и просто запустите
`Расшифровать.bat` двойным кликом. Готовые документы появятся в `output\`.

**Способ 4 — командная строка.** Даёт доступ ко всем настройкам:

```
.venv\Scripts\python.exe transcribe.py "D:\Записи\совещание.mp4" -o output
```

Поддерживаются mp3, wav, m4a, ogg, opus, flac, mp4, mkv, avi, mov, webm и
другие форматы — видео обрабатывается наравне с аудио, звуковая дорожка
извлекается автоматически.

## Словарь терминов: исправление ошибок

Whisper уверенно путает редкие слова — фамилии, названия, профессиональный
жаргон. Словарь лечит именно это, и работает он с двух сторон:

1. **До распознавания** список уходит в модель как подсказка (`hotwords`), и
   она начинает ожидать эти слова. Это главное: исправлять нечего, если
   распозналось сразу верно.
2. **После распознавания** то, что всё же вышло неверно, правится сравнением
   по похожести (библиотека RapidFuzz).

Словарь лежит в `glossary.txt` и редактируется на вкладке **«Словарь»**:

```
EBITDA
гносеогенная
Рац Наталья Александровна
гносиогенная => гносеогенная     # явная замена, применяется всегда
```

**Чего словарь не умеет.** Он не понимает смысл. Логические ошибки, потерянное
«не», перепутанные по смыслу слова, кривое согласование — всё это остаётся:
программе не с чем сравнивать, она знает только список правильных написаний.
Для таких ошибок нужна языковая модель, которая читает текст целиком.

### Почему не просто «похожие слова»

Наивное сравнение строк на русском ломает грамматику. «Платона» похоже на
«Платон» на 92% — и замена по порогу превратила бы родительный падеж в
именительный. Поэтому сравнивается только основа слова, а окончание исходного
сохраняется, плюс действуют два правила:

* расхождение **только в последних буквах** — это падежное окончание, а не
  ошибка: «Аристотеля» не станет «Аристотель»;
* первые буквы обязаны совпасть: «биологическое» и «мифологическое» похожи
  одним хвостом, и без этого условия одно подменялось другим — такое
  срабатывание нашлось на реальной лекции.

Проверено на 32 тысячах слов реальных расшифровок: **2 замены, обе верные,
ложных нет**. Если слово искажено до неузнаваемости, помогает явная
замена через `=>`.

Ключи командной строки: `--glossary ПУТЬ` и `--no-glossary`.

## Какую модель выбрать

Замеры на RTX 4050 Laptop (6 ГБ), запись 40 секунд русской речи.
«Видеопамять» — сколько нужно вместе с разделением говорящих: вторая модель
живёт в памяти рядом с первой и добавляет около 1,8 ГБ. «Скорость» — во
сколько раз распознавание быстрее реального времени, без учёта разделения
говорящих.

| Модель | На диске | Видеопамять | Скорость | Когда брать |
|---|---|---|---|---|
| **large-v3** | 2,9 ГБ | 5,2 ГБ | ~12× | когда важна точность |
| **large-v3-turbo** | 1,5 ГБ | 4,6 ГБ | ~30× | разумный выбор по умолчанию |
| **medium** | 1,4 ГБ | 4,0 ГБ | ~17× | если видеопамяти мало |
| **small** | 0,5 ГБ | 2,7 ГБ | ~28× | черновой просмотр, слабые машины |

Неочевидное: **large-v3-turbo быстрее не только large-v3, но и вчетверо
меньшей small**. У turbo всего четыре слоя декодера, а именно декодер
определяет скорость. Поэтому брать small имеет смысл только там, где не
хватает видеопамяти на turbo.

Без видеокарты NVIDIA всё работает на процессоре, но примерно в 20 раз
медленнее — там осмысленна только `small`.

В окне под списком моделей показано, сколько модель требует и хватает ли
этого на вашей машине. Установщик подбирает модель по видеокарте сам.

## Полезные ключи

| Ключ | Зачем |
|---|---|
| `--num-speakers 2` | известно точное число говорящих — заметно повышает точность разделения |
| `--min-speakers 2 --max-speakers 5` | известны границы |
| `--language ru` | пропустить автоопределение языка |
| `--no-diarization` | быстрее, без подписей говорящих |
| `-o output` | складывать все документы в одну папку |
| `--initial-prompt "..."` | подсказка с именами и терминами: «Совещание. Участники: Иванов, Петрова. Термины: EBITDA, Транскрибатор.» — заметно улучшает написание имён собственных |
| `--model large-v3-turbo` | втрое быстрее, качество чуть ниже |
| `--speaker-prefix "Участник"` | другая подпись вместо «Спикер» |
| `--device cpu --compute-type int8` | если видеокарта занята другой задачей |

Полный список: `.venv\Scripts\python.exe transcribe.py --help`

## Передача коллегам

Установщик собирается командой `installer\build.py` и выкладывается на
страницу [Releases](https://github.com/6snowyfox6/Transcribator/releases).
Весит около 2 МБ, передаётся любым способом.

**Что происходит при установке.** Папку установки можно выбрать; по умолчанию
предлагается `%LOCALAPPDATA%\Programs\Transcribator`. Права администратора не
нужны, в системе ничего не меняется. После копирования файлов установщик сам
находит или скачивает Python, определяет видеокарту, ставит подходящий вариант
PyTorch (с CUDA или процессорный) и скачивает модель под объём видеопамяти.
Всё это идёт в окне установщика с движущейся полосой — никаких чёрных консолей
не появляется. Занимает 20–40 минут и около 6 ГБ трафика, нужен интернет.
Галочка на шаге выбора компонентов позволяет отложить загрузку модели.

**Путь установки должен быть коротким.** Внутри PyTorch есть файлы с очень
длинными именами, и в глубоко вложенной папке установка упрётся в предел длины
пути Windows (260 символов). Установщик проверяет это на странице выбора папки
и не даёт выбрать слишком длинный путь.

**Удаление.** Через «Параметры → Приложения» или ярлык «Удалить Транскрибатор»
в меню «Пуск». Удаляются окружение Python (около 5 ГБ), ярлыки и служебные
файлы. Расшифровки, история и токен остаются — программа скажет, где они
лежат, чтобы решение принял человек.

**Разделение говорящих у коллеги.** Ваш токен передавать нельзя — это пароль
от вашего аккаунта Hugging Face, и условия модели принимаются персонально.
При первом запуске программа сама покажет окно с тремя шагами, откроет нужные
страницы и проверит введённый токен. Занимает пару минут. Кто не хочет
возиться — нажимает «Пропустить» и получает сплошной текст с таймкодами;
настроить позже можно кнопкой «Настроить доступ…».

Пока рабочего токена нет, галочка «Разделять говорящих» заблокирована: иначе
расшифровка запускалась бы и падала на середине. Как только токен проверен,
галочка включается сама.

**Пересборка установщика** после правок в коде:

```
.venv\Scripts\python.exe installer\build.py
```

Нужен Inno Setup: `winget install --id JRSoftware.InnoSetup -e`.

## Если что-то сломалось

**«Не удалось загрузить модель разделения говорящих»** — не пройден один из
шагов с токеном выше. Чаще всего забывают нажать кнопку согласия на странице
модели: одного токена недостаточно.

**`CUDA out of memory`** — на видеокарте 6 ГБ, и другое приложение заняло
память. Закройте его либо запустите с `--compute-type int8_float16` или
`--batch-size 1`.

**«CUDA недоступна — переключаюсь на процессор»** — обновите драйвер NVIDIA.
На процессоре расшифровка тоже работает, но примерно в 20 раз медленнее.

**Окно не открывается** — разбор ошибки записывается в `gui_error.log`
рядом с `gui.py`.

**Переустановка окружения с нуля:**

```
rmdir /s /q .venv
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu128
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Технические заметки

Python 3.12, а не более новый 3.14, стоит здесь намеренно: `pyannote.audio`
тянет за собой PyTorch и десяток научных пакетов, для которых сборок под 3.14
пока нет. Системный Python 3.14 не тронут, окружение полностью изолировано
в `.venv`.

На Windows библиотеки cuDNN и cuBLAS лежат внутри пакета `torch`, а движок
`ctranslate2` их там не ищет — `transcribe.py` подсказывает ему путь при
запуске (`_register_torch_cuda_dlls`). Отдельно ставить CUDA Toolkit не нужно.

Whisper без «затравки» склонен писать текст без точек в конце предложений,
поэтому скрипт подставляет короткий образец нужного стиля на языке записи
(`STYLE_PROMPTS`). Свой `--initial-prompt` эту подстановку заменяет.

Обе модели держатся в видеопамяти одновременно и переиспользуются для всех
записей пакета: замер показал 5.8 ГБ из 6.1 ГБ — впритык, но помещаются, а
перезагрузка моделей стоила бы около 35 секунд на каждый файл. Если памяти
всё же не хватит (например, её занял браузер), `transcribe.py` поймает ошибку,
перейдёт в режим одной модели и повторит шаг — расшифровка не прервётся,
только замедлится.

Окно (`gui.py`) не считает ничего само: оно запускает `transcribe.py`
отдельным процессом с ключом `--progress-json` и читает поток событий. Поэтому
интерфейс не подвисает на загрузке модели, а «Остановить» гарантированно
прекращает работу — процесс просто снимается.

История пишется в `history.jsonl` построчно (одна расшифровка — одна строка
JSON). Файл только дописывается в конец, поэтому не портится при аварийном
завершении, а битую строку чтение просто пропускает.

Абзац внутри речи одного человека разрывается только на границе предложения.
Раньше правило было «длина плюс пауза», и фраза рвалась посреди себя: «В»
оставалось в конце абзаца, а «17 веке возникнет наука» начинало следующий.
На реальных расшифровках так ломались 25 фраз. Разрыв при смене говорящего —
другое дело, он законен: в диалоге люди перебивают друг друга.

Четыре места, где Windows наказывает за кодировку, и все уже наступлены:
`.bat` cmd.exe читает в кодировке OEM — поэтому внутри `.bat` только латиница
(кириллица в комментариях разбиралась как команды); `.ps1` Windows PowerShell
5.1 без BOM читает в системной кодировке — поэтому `installer\build.py` перед
каждой сборкой принудительно проставляет BOM, иначе установка падает молча;
`Set-Content -Encoding utf8` в PowerShell 5.1, наоборот, BOM дописывает — и
`machine.json` приходится читать как `utf-8-sig`, иначе `json.loads` падает;
вывод питоновских скриптов внутри PowerShell попадал в лог кракозябрами, пока
не выставили `PYTHONIOENCODING=utf-8`. Первые две проверки встроены в сборку.

Ctrl+V в полях ввода тоже пришлось чинить: Tk привязывает сочетания к символам,
а при русской раскладке та же клавиша даёт «м», и вставка молча не работала.
`tkutil.py` ловит нажатие по коду клавиши, независимо от раскладки.

Полосу загрузки в установщике двигает не PowerShell, а сам установщик:
`bootstrap.ps1` пишет в `progress.txt` строку вида `18|62|Ставлю PyTorch`
(текущий процент, потолок шага и подпись), а процедура `RunBootstrap` в
`Transcribator.iss` читает её раз в полсекунды и между отметками плавно
подводит полосу к потолку — иначе на пятнадцатиминутной загрузке PyTorch она
выглядела бы зависшей.

Установщик не ставит второй Python, если подходящий уже есть в системе:
установщик с python.org при совпадении версии не создаёт вторую копию, а
«чинит» существующую и молча игнорирует путь установки. Поэтому сначала идёт
поиск Python 3.10–3.13 с работающим tkinter, и своё окружение создаётся из
него через `venv`.
